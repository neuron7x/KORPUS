## Підняти й перевірити, що воно відповідає

Цього розділу тут не було, і його відсутність була вадою, не пропуском: свіжий клон
віддавав `503` на кожному ендпоінті, а рядок, потрібний щоб зрушити, не траплявся
в ЖОДНОМУ `.md` — лише в `config_policy.py:49` і в двох файлах CI.

```bash
make api-install                       # venv із локів за хешами
make bootstrap                         # схема + демонстраційна фікстура
KORPUS_AUTH_MODE=dev \
KORPUS_DEV_MODE_ACKNOWLEDGEMENT=I_ACKNOWLEDGE_DEV_AUTH_IS_INSECURE \
  make api-run                         # 127.0.0.1:8000
```

`auth_mode` за замовчуванням `disabled`, і це навмисно: режим розробника вимагає, щоб
його увімкнули ДВІЧІ — прапорцем і дослівним визнанням незахищеності. Мовчазний
дефолт «увімкнено» був би fail-open, тому рядок незручний за задумом. Незручним він
має бути, невидимим — ні.

**`/health` НЕ є свідченням готовності.** Він відповідає `200 {"status":"ok"}` навіть
коли сервіс не здатен відповісти на жодне питання. Стан, який щось означає, читається
з `/ready`:

```bash
curl -s localhost:8000/ready | python3 -m json.tool
```

`ready: false` називає ВСІ хибні предикати одразу — ревізію схеми, стан якоря
й журналу. Виміряно 06.09.2026: публічний сервіс тримав `200` на `/health` три доби
поспіль, маючи `/ready` = `503` через незастосовану міграцію `0023`. Ніхто не помітив,
бо все, що дивилось на сервіс, дивилось на `/health`.

**Корпус за замовчуванням порожній.** `make bootstrap` інжестить одну фікстуру, а не
робочий корпус: `var/` цілком у `.gitignore`, тож документи не подорожують із репозиторієм.
Свіжий клон на будь-яке справжнє питання відповість `insufficient_evidence` — і це
правильна поведінка порожньої системи, а не вада добору.
