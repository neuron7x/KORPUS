# Вхідний пакет доменного TEVV — усе, крім людських міток

**Дайджест джерела:** `693d03ad9468…` — прив'язка ledger'а й предмет цього пакета.
Коміта тут навмисно немає: документ у дереві не здатен назвати власний коміт (див. §16
пакета власника).
**Зібрано:** `python3 reports/tevv-bundle/assemble.py` (детерміновано; повторний запуск
дає той самий `query_set_sha256`)

Цей пакет існує тому, що три блокери релізу — `real_domain_corpus_tevv`,
`independent_tevv`, `production_like_tevv_environment` — не можуть бути закриті машиною.
Політика (`evals/GOLD_ANNOTATION_LEDGER_TEMPLATE.json`) вимагає **двох незалежних
предметних анотаторів**, згоди Cohen's kappa **≥ 0,6** і **судді, який не є жодним із
них**. Два контексти LLM не є двома анотаторами, і жодне число, виведене з них, не є
виміром згоди. Тому міток тут немає й не буде.

Машина зробила все інше.

## Що вже готове

| файл | що це |
|---|---|
| `query_set.jsonl` | **299 унікальних запитів** зі семи наборів дерева, дедупліковані за текстом; політика вимагає ≥200 |
| `holdout.json` | **59 сліпих холдаутів**, обраних ДЕТЕРМІНОВАНО за `sha256(id)` — тобто ДО того, як хтось побачив відповіді; політика вимагає ≥40 |
| `worksheet-annotator-1.csv`, `worksheet-annotator-2.csv` | аркуші з порожнім стовпцем `label` — по одному рядку на запит |
| `ledger.json` | шаблон із ЗАПОВНЕНИМИ прив'язками: дайджест дерева, реліз, `query_set_sha256`, `annotation_protocol_sha256` |
| `assemble.py` | сам збирач — щоб пакет був відтворюваним, а не подарунком |

Дедуплікація за текстом навмисна: один запит із двох наборів дав би два рядки, і згода
анотаторів рахувалася б двічі на тому самому предметі.

## Що лишається людям — рівно дві дії

1. **Два незалежні предметні анотатори** заповнюють стовпець `label` у своєму аркуші.
   Вони не мусять бачити аркуш один одного; холдаут уже відокремлений.
2. **Суддя, який не є жодним із них**, розв'язує розбіжності.

## Одна команда після цього

```
python3 scripts/audit_gold_annotations.py --ledger reports/tevv-bundle/ledger.json
```

Вона рахує Cohen's kappa, звіряє покриття холдауту, перевіряє прив'язки й пише
`reports/GOLD_ANNOTATION_CURRENT.json`. Далі `make production-tevv` бере його як доказ.

## Чого цей пакет НЕ робить

Він не робить TEVV пройденим. Він робить його **виконуваним однією людською дією
замість кампанії з нуля**. Якщо анотатори не досягнуть kappa ≥ 0,6, гейт відмовить — і
це правильна відмова, а не збій пакета: низька згода означає, що предмет визначено
недостатньо чітко, і це знання дорожче за зелений колір.

Пакет лежить у `reports/`, який НЕ входить у `source_tree_sha256`. Його поява не зсуває
кандидата й не знецінює жодного доказу, знятого на ньому.
