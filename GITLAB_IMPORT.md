# Git import — KORPUS v0.1.0

Authoritative release identity: `v0.1.0`. Do not infer a branch or reuse an older bundle name.

The canonical repository package may carry either the release bundle generated by
`package_repository.sh` (`KORPUS_SYSTEM_v0.1.0.bundle`) or the recovery full-history
bundle (`KORPUS_v0.1.0_FULL_HISTORY.bundle`). Select exactly one existing bundle:

```bash
bundle="$(find . -maxdepth 1 -type f \
  \( -name 'KORPUS_SYSTEM_v0.1.0.bundle' -o -name 'KORPUS_v0.1.0_FULL_HISTORY.bundle' \) \
  -print -quit)"
test -n "$bundle" && test -f "$bundle"
git clone "$bundle" korpus
cd korpus
git checkout v0.1.0
test "$(git rev-parse HEAD)" = "$(git rev-parse v0.1.0^{commit})"
python3 scripts/check_release_identity.py --require-git-tag
python3 scripts/verify_source_manifest.py
```

The two final commands are mandatory. A successful clone is not evidence that the
bundle, tag and source manifest describe the same release. Production promotion is
separate and remains blocked unless `reports/PRODUCTION_ASSURANCE_REPORT.json` is PASS
and the protected-tag signing/trust chain verifies.
